<objective>
Close the two verification gaps in `13-VERIFICATION.md` (truths #16 and #17), which are the
same two defects `13-REVIEW.md` raised as CR-01 (Critical) and WR-01 (Warning) and which are
still present in the shipped Plan 13-03 code:

1. `update_qa` accepts a whole-row replace that changes an item's `type` away from
   `'category'` even when other `qa_items` rows on the same page still point at it via
   `category_id`. The PUT returns 200 and silently orphans those questions — they keep a
   `category_id` pointing at a row that is no longer `type='category'`, so
   `app/routers/content.py` (which filters categories on `type = 'category'`) can never
   surface them again.
2. `delete_qa` issues `DELETE FROM qa_items` with no dependent-row check. With
   `PRAGMA foreign_keys=ON` (`app/db.py:9`) and `qa_items.category_id REFERENCES qa_items(id)`
   defaulting to `NO ACTION`/RESTRICT, deleting a category that still has questions raises an
   unhandled `sqlite3.IntegrityError` ("FOREIGN KEY constraint failed"). No data is lost
   (`conn.commit()` is never reached) but the admin gets a generic 500 instead of an
   actionable error.

Both fixes are already fully specified in `13-REVIEW.md`. This is a surgical, application-layer
fix: one shared page-scoped dependent-row lookup plus two call sites. It completes the
`category_id` referential-integrity decision that `13-CONTEXT.md` left to the planner
("enforced at the application layer ... planner decides where") and requires **no schema
change** (`13-CONTEXT.md` locks "No schema changes this phase"; the `app/db.py:53` comment
already states this constraint is application-enforced).

Purpose: CONTENT-03's edit/delete path currently corrupts data on one route and crashes on the
other for the most common realistic case — a category that has questions.
Output: A dependent-row guard in `app/routers/pages.py` + 2 regression tests in
`tests/test_pages.py` that fail against the current code and pass after the guard lands.

Scope discipline (CLAUDE.md §3 "Surgical Changes"): touch only `update_qa`, `delete_qa`, and a
sibling helper next to `_validate_category_ref`. Do NOT refactor the duplicated HMAC guard
(IN-01), add multi-node cycle detection (IN-02), rename the `type` param (IN-03), touch
`_store_pages_and_subscribe` (WR-02), or modify `app/routers/content.py` — its
`{items:[{id,type,title}]}` / `{id,type,title,body}` contract is load-bearing and out of bounds.
</objective>
