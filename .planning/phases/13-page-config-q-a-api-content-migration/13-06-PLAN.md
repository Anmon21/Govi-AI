<objective>
Close the single remaining gap in `13-VERIFICATION.md` (truth #25), which is the same defect
`13-REVIEW.md` raised as CR-01 (Critical) and which is still present in the shipped Plan 13-04 code:

`load_vault_items()` returns an empty list — printing only a warning — whenever
`settings.vault_path` is unset or does not point at a directory (`scripts/seed_qa.py:22-24`).
`seed()` never checks that result. It proceeds unconditionally to
`DELETE FROM qa_items WHERE page_id = ?` (`scripts/seed_qa.py:81`), inserts nothing, reaches
`conn.commit()` (`scripts/seed_qa.py:120`), and prints
`Seeded 0 categories, 0 questions for page <id>` as if the migration had succeeded. Both the
reviewer and the verifier independently reproduced total data loss with a success message: a page
with real `qa_items` rows ends with zero rows, exit code 0, no error.

This is not a theoretical failure mode on this machine. `settings.vault_path` defaults to `""`
(`app/config.py:8`), **and the repo's own `.env` currently contains the line `VAULT_PATH=`
(empty value)**. The actual one-time migration run — the only run this script exists for — would
take the destructive branch as the repository stands today.

Purpose: DB-02 is `⚠️ PARTIALLY SATISFIED`. The happy path is solid and already covered by truths
#20–#24; what is missing is fail-closed behaviour on the one input that matters most.
Output: A four-line guard in `scripts/seed_qa.py` plus regression tests in `tests/test_seed_qa.py`
that fail against the current code and pass after the guard lands.

quoted in `13-REVIEW.md` CR-01 contains two independent changes. **Only the first is in scope:**

  `items = load_vault_items()` and the `DELETE`.
