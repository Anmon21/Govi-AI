<objective>
Deliver the one-time seed script (DB-02, D-03) that migrates the Obsidian vault's Q&A
content into the database for a target Page. It takes `--page-fb-id`, resolves it to the
internal `pages.id`, wipes that page's `qa_items` and re-inserts from the vault
(idempotent wipe+reload), and ensures a default `page_configs` row exists so the read API
and bot never hit a missing config.

Purpose: DB-02 — retire the vault as the content store by getting existing content into
the DB, safely re-runnable.
Output: `scripts/seed_qa.py`, `tests/test_seed_qa.py`.

Note: This script is fully self-contained — it reproduces the vault frontmatter-parsing
logic locally (lifted from `content.py::load_vault`, which Plan 13-01 deletes). Do not
import from `app.routers.content`. The reference copy of that logic lives in
`13-PATTERNS.md` (reproduced in full) so this plan does not depend on Plan 13-01's file
state.
</objective>

  <action>
    Create `scripts/seed_qa.py` following `init_db.py`'s conventions (sys.path.insert shim,
    `from app.config import settings`, `from app.db import get_connection`, plain `print()`
    progress, `if __name__ == "__main__"` guard).

    Reproduce the vault frontmatter-parsing logic locally as `load_vault_items()` (lift from
    content.py `load_vault` / the reproduction in 13-PATTERNS.md): scandir
    `settings.vault_path` for `*.md`, `frontmatter.load` each, skip entries whose `enabled`
    is not boolean-True, require non-empty string `id`/`type`/`title`, allow optional
    string `category`, and return a list of `{id, type, title, category, body}` dicts.
    Required imports: `os`, `yaml`, `frontmatter`, plus `argparse`.

    Parse `--page-fb-id` (required string) with `argparse`.

    Resolve the page: `SELECT id FROM pages WHERE page_fb_id = ?` (do NOT filter
    `is_active` — an operator may deliberately seed a test/inactive page). If no row,
    `print` a clear error and `sys.exit(1)` — write nothing.

    Migration (all inside one connection, wipe+reload, idempotent):
    1. `DELETE FROM qa_items WHERE page_id = ?` (unconditional wipe of this page's Q&A).
    2. Pass 1 — insert every vault item with `type == "category"`:
       `INSERT INTO qa_items (page_id, type, title, body, enabled) VALUES (?, 'category', ?, ?, 1)`;
       build a `{vault_string_id: new_int_id}` map from `cur.lastrowid`.
    3. Pass 2 — insert every `type == "question"`: resolve its `category` (vault string id)
       through the map to the new integer `category_id`. If a question references a category
       id absent from the map, `print` a warning and skip that question (do not abort the
       whole run). `INSERT INTO qa_items (page_id, type, title, body, category_id, enabled)
       VALUES (?, 'question', ?, ?, ?, 1)`.
    4. Ensure a `page_configs` row exists using the WHERE-NOT-EXISTS idiom from init_db.py:
       `INSERT INTO page_configs (page_id, welcome_text, menu_json) SELECT ?, '', '['+']'
       WHERE NOT EXISTS (SELECT id FROM page_configs WHERE page_id = ?)` — welcome_text ''
       and menu_json '[]' match schema defaults; escalation columns stay null.
    5. `conn.commit()`, `conn.close()` in `finally`. `print` a summary line with the counts
       of categories and questions inserted (e.g. "Seeded N categories, M questions for page ...").

    `?`-placeholders only, never f-strings for SQL. Wrap the DB work in
    `try/finally: conn.close()` (this is a script, not a router — the router "no try/except"
    rule does not apply; still, keep error handling minimal — let unexpected DB errors surface).
  </action>
