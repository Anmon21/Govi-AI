## Conversational Copy Contract

This section replaces the standard Copywriting Contract for Messenger-native
phases. Every string that reaches a user must be declared here. Executor
MUST use these exact strings — no paraphrasing.

### Greeting Messages

These are the only strings changed by this phase. All other message strings
in index.ts remain unchanged.

#### First-time welcome (new PSID — no name in Map yet)

Trigger: GET_STARTED postback or MENU_MAIN quick reply, PSID not in userNameCache

```
Welcome to Govi! I can help with product questions or connect you with a human.
```

Quick replies: MAIN_MENU_QUICK_REPLIES (unchanged)

Note: This is the existing `sendWelcomeMessage` text. First-time users see
the generic greeting while the Graph API fetch runs in the background to
populate userNameCache for next time.

#### Returning user welcome (PSID already in Map — name known)

Trigger: GET_STARTED postback or MENU_MAIN quick reply, PSID found in
userNameCache with a non-empty first name

```
Welcome back, {firstName}! How can I help you today?
```

Quick replies: MAIN_MENU_QUICK_REPLIES (unchanged)

Constraint: `{firstName}` is the raw first_name value from the Graph API
response. No truncation, no casing transformation beyond what the API returns.

#### Fallback greeting (Graph API returned no name or failed)

Trigger: PSID in userNameCache but stored as empty string `""`, or Map lookup
returns undefined after a failed fetch that stored the empty sentinel

```
Welcome to Govi! I can help with product questions or connect you with a human.
```

Quick replies: MAIN_MENU_QUICK_REPLIES (unchanged)

Note: Same text as first-time welcome. The user sees no indication that a
name lookup was attempted or failed. No error text is shown.

### No New Quick Reply Labels

This phase introduces no new quick reply buttons. MAIN_MENU_QUICK_REPLIES

## Interaction Flow Contract

### Name Fetch Timing

The Graph API call to fetch `first_name` happens on the FIRST inbound event
from a PSID — before routing to any handler. This means:

1. Event arrives from unknown PSID
2. Bot calls `GET /{GRAPH_API_VERSION}/{psid}?fields=first_name`
3. On success: store first name in `userNameCache` Map
4. On failure (network error, 4xx, missing field): store empty string `""` as
   sentinel so the fetch is not retried on every subsequent message
5. Route event to handler normally

For subsequent events from the same PSID, step 2-4 are skipped entirely —
Map lookup only.

### sendWelcomeMessage Behavior After This Phase

`sendWelcomeMessage(recipientId)` must check `userNameCache`:

```
if name found and non-empty → "Welcome back, {name}! How can I help you today?"
else                         → "Welcome to Govi! I can help with product questions or connect you with a human."
```

Both branches send MAIN_MENU_QUICK_REPLIES.

### Error Surface to User

Zero. A Graph API failure is invisible to the user. The bot sends the generic
greeting and logs the failure internally:

```
console.error("fetchUserName failed:", err.message, err.response?.data)   // Axios error
console.error("fetchUserName failed (unexpected):", err.message)           // non-Axios error
```

## State Contract

| Store | Type | Key | Value | Lifespan |
|-------|------|-----|-------|----------|
| userNameCache | `Map<string, string>` | PSID string | first_name or `""` sentinel | In-memory, reset on bot restart |

Empty string `""` as sentinel is deliberate — it signals "fetch was attempted
and failed" so the bot does not retry on every message from that PSID.

---

## Graph API Contract

| Property | Value |
|----------|-------|
| Endpoint | `GET https://graph.facebook.com/{GRAPH_API_VERSION}/{psid}` |
| Query params | `fields=first_name&access_token={PAGE_ACCESS_TOKEN}` |
| Success shape | `{ first_name: string }` |
| Failure handling | catch → store `""` sentinel → continue |
| Token exposure | Must follow SEC-03: never log full Axios error object |

This lookup uses the existing `PAGE_ACCESS_TOKEN` and `GRAPH_API_VERSION`
constants already in scope. No new env vars required.
