<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Graph API response → userNameCache | First_name value from Facebook is an untrusted string from an external API; stored directly as-is |
| userNameCache → Messenger message | Cached name is interpolated into outbound message text sent to Messenger |
| axios error → console.error | Error objects from failed Graph API calls may contain PAGE_ACCESS_TOKEN in config.url |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-01 | Information Disclosure | fetchUserName catch block | mitigate | SEC-03: log only err.message and err.response?.data — never log the axios error object itself (config.url contains PAGE_ACCESS_TOKEN as query param). Two-branch catch pattern enforced in task action and verified by code review of every console.error call. |
| T-09-02 | Tampering | first_name → message text | accept | first_name is a plain-text string from Facebook's Graph API, interpolated into a Messenger text message (not HTML). No XSS risk: Messenger renders as plain text only. Meta controls the field value — a hostile name value ("&lt;script&gt;") is rendered as a literal string in Messenger chat. |
| T-09-03 | Denial of Service | fetchUserName per-PSID | accept | One Graph API GET per new PSID per bot lifetime (until restart). Rate limiting risk is negligible for expected traffic. No retry loop — sentinel pattern prevents unbounded calls for any single PSID. |
| T-09-04 | Information Disclosure | userNameCache in-memory state | accept | Map lives in Node.js process memory only. Not written to disk, not logged, not exposed via any API endpoint. Accessible only within the bot process. Resets on restart per locked decision (STATE.md in-memory Map for v1.1). |
| T-09-05 | Spoofing | PSID as Map key | accept | PSID is provided by Facebook via the signed webhook payload (signature verification already enforced in Phase 1 verifySignature middleware). A spoofed PSID would require breaking the HMAC-SHA256 signature — out of scope for this phase. |
</threat_model>
