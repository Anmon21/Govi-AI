<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI invoker → scripts/init_db.py | A developer or deployment runner executes the script; the only input is settings.db_path (from env); no user-supplied SQL ever reaches this script |
| scripts/init_db.py → filesystem | The script creates a new file at settings.db_path; if that path resolves to a sensitive location it could overwrite an existing file (mitigated by CREATE TABLE IF NOT EXISTS — does not destroy existing data) |
| .gitignore → version control | New patterns prevent accidental commit of the DB file containing future encrypted tokens |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-SQL | Tampering | scripts/init_db.py | mitigate | Script never accepts user input — only reads settings.db_path (env-controlled) and calls init_schema (parameterless DDL). Inherits Plan 01's parameterized-query stance; acceptance criteria confirms no SQL string interpolation enters this file. |
| T-10-KEY | Information Disclosure | scripts/init_db.py — Fernet key | mitigate | Acceptance criteria gate: `grep -cE "fernet\|crypto" scripts/init_db.py` returns 0. This script deliberately does NOT touch the Fernet key or the crypto module — keys never traverse the init runner. |
| T-10-DB-OVERWRITE | Tampering | filesystem at settings.db_path | accept | If a developer points DB_PATH at an existing file, CREATE TABLE IF NOT EXISTS prevents schema overwrite of existing tables but adjacent tables/data could coexist. Treated as developer-config risk; documented via DB_PATH default of "govi.db" (project root, gitignored). |
| T-10-DB-COMMIT | Information Disclosure | git commit of govi.db | mitigate | .gitignore extended with `*.db`, `*.db-wal`, `*.db-shm` patterns; acceptance criteria verifies all three patterns are present and that `git status` does not list the created DB after Task 1 runs. |
