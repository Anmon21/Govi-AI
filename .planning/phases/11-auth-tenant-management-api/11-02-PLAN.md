<endpoint_contracts>
<!-- Exact HTTP contracts. Plan 03 tests verify these byte-for-byte. -->

POST /auth/login
  Request body: LoginRequest { email: str, password: str }
  Success 200: TokenResponse { access_token: str, token_type: "bearer" }
  Errors:
    - 401 { "detail": "Invalid credentials" } — unknown email, wrong password, or is_active=0

POST /admin/tenants  (Depends require_super_admin)
  Request body: CreateTenantRequest { email: str, password: str }
  Success 201: TenantResponse { id: int, email: str, is_active: bool, is_super_admin: bool, created_at: str }
  Errors:
    - 409 { "detail": "Email already exists" } — UNIQUE constraint on tenants.email
    - 401 { "detail": "Invalid token"|"Token expired" } — missing/expired JWT
    - 403 { "detail": "Admin access required" } — JWT with role!="super_admin"
  Notes: password is bcrypt-hashed before INSERT; password_hash is NEVER in the response; is_super_admin is forced to 0 (clients only).

GET /admin/tenants  (Depends require_super_admin)
  Success 200: List[TenantListItem] where TenantListItem = { id: int, email: str, is_active: bool, created_at: str, page_count: int }
  Excludes rows where is_super_admin = 1
  page_count counts pages where pages.is_active = 1 (LEFT JOIN ON pages.tenant_id = tenants.id)

DELETE /admin/tenants/{tenant_id}  (Depends require_super_admin)
  Success 200: { "detail": "Tenant {id} deactivated", "pages_deactivated": <int> }
  Errors:
    - 404 { "detail": "Tenant not found or already inactive" } — id missing or already is_active=0
    - 403 { "detail": "Cannot delete your own account" } — tenant_id == int(current["sub"])
  Behavior: UPDATE tenants SET is_active=0 WHERE id=? AND is_super_admin=0; UPDATE pages SET is_active=0 WHERE tenant_id=?; both run in a single transaction with one explicit conn.commit().

GET /tenants/me  (Depends get_current_tenant)
  Success 200: TenantResponse { id, email, is_active, is_super_admin, created_at } for the calling tenant
  Errors:
    - 401 — missing/expired JWT (auto from get_current_tenant)
    - 404 { "detail": "Tenant not found" } — sub claim points to deleted row (defensive)
  Notes: Looks up the row by `id = int(current["sub"])`; never returns password_hash.
</endpoint_contracts>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP request -> /auth/login | Untrusted client input (email, password); enters via Pydantic LoginRequest |
| HTTP request -> Authorization: Bearer header | Untrusted token; oauth2_scheme parses; verify_token validates signature/expiry |
| JWT claims -> tenant_id (sub) lookup | Server trusts the `sub` claim only after signature verification; `int(current["sub"])` parameterizes SELECT |
| Plaintext password -> bcrypt verify | Plaintext password held in memory only during request; never logged; passed to pwd_context.verify and discarded |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-11-09 | Spoofing | POST /auth/login | mitigate | bcrypt verify with pwd_context.verify — timing-safe comparison; identical 401 response shape for unknown-email and wrong-password (prevents user enumeration) |
| T-11-10 | Elevation of Privilege | Deactivated tenant login | mitigate | `WHERE email = ? AND is_active = 1` in login SELECT (Pitfall 3) — deactivated row never reaches the bcrypt comparison step, so 401 returns deterministically |
| T-11-11 | Elevation of Privilege | /admin/tenants endpoints | mitigate | `Depends(require_super_admin)` returns 403 if JWT role != "super_admin" (D-04). Three protected routes; each declares the dependency |
| T-11-12 | Information Disclosure | password_hash in responses | mitigate | password_hash never appears in any Pydantic response model (TenantResponse, TenantListItem, DeleteResponse, TokenResponse all omit it); SELECT statements project only response-safe columns |
| T-11-13 | Tampering | SQL injection via email/password | mitigate | Raw SQL with `?` placeholders throughout (project convention from app/db.py); no f-string interpolation in any SQL body |
| T-11-14 | Elevation of Privilege | Super-admin self-deletion lockout | mitigate | DELETE /admin/tenants/{id} returns 403 if `tenant_id == int(current["sub"])` (Pitfall 5); secondary defense via `WHERE is_super_admin = 0` filter |
| T-11-15 | Information Disclosure | Super-admin row in tenant list | mitigate | `WHERE t.is_super_admin = 0` in list SELECT (Pitfall 4) — super-admin row is invisible to /admin/tenants consumers |
| T-11-16 | Information Disclosure | Cross-tenant read on /tenants/me | mitigate | SELECT uses `WHERE id = ?` parameterized by `int(current["sub"])` from JWT; tenant A's JWT cannot read tenant B's row because the sub claim is signed |
| T-11-17 | Tampering | Soft-delete cascade race | mitigate | Both `UPDATE tenants` and `UPDATE pages` share one conn + one commit (Pattern 4 + "Don't Hand-Roll" transaction safety) — partial deactivation not possible |
| T-11-18 | Denial of Service | bcrypt cost under brute force | accept | Default cost (12) is industry standard; rate limiting is deferred to v1.3 per RESEARCH.md Security Domain table |
