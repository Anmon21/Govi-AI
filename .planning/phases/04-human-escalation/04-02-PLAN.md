<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Customer Messenger → /webhook | Untrusted JSON; SEC-01 HMAC verification already gates this. Escalation handler trusts senderId comes from the verified body. |
| Bot → Graph API /me/pass_thread_control | Outbound call carries PAGE_ACCESS_TOKEN in query params; SEC-03 forbids logging the bare axios error (it embeds the full URL including the token). |
| Bot → Admin Messenger | Admin notification body is interpolated with lastMessage (customer-supplied text). Messenger does not render HTML, so XSS is not a vector; markdown is not interpreted either. Length only — last-message strings are bounded by Messenger's message size limit (2000 chars) so unbounded growth in the body is not in scope. |
| Process env → log | ADMIN_PSID and PAGE_ACCESS_TOKEN must never be interpolated into log lines. |

| T-4-02 | Tampering / Integrity (Graph API rejection) | passThreadControl when app is not Primary Receiver | mitigate | Wrap the call in try/catch using the same axios.isAxiosError narrowing as sendMessage; treat HTTP-200-with-error-body the same way (SEC-02 pattern); also log a "pass_thread_control Graph API error:" line for ops triage.
