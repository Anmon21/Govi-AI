## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator → process | `VAULT_PATH` env var is operator-controlled; treated as trusted infrastructure config (not user input). |
| filesystem → process | Vault directory contents (`.md` files + frontmatter) are operator-controlled; the loader parses YAML. |
| network → process | Anyone with HTTP access to the FastAPI port can call GET /content/{id} and POST /content/reload. CORS is `allow_origins=["*"]` (pre-existing). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-2-01 | Tampering | `VAULT_PATH` value pointing at sensitive directories (e.g., `/`, `/etc`) | accept | `VAULT_PATH` is operator-set via .env on a single-tenant deployment. `os.scandir` + `entry.is_file()` + `.endswith(".md")` ensures only top-level .md files are read; no `os.walk`, no symlink-following (default scandir behavior reads symlink targets but not directories — D-02 disables recursion). For v1 single-operator deployment this is acceptable. Document in README: VAULT_PATH must point at a dedicated content directory. |
| T-2-02 | Tampering | Malformed YAML frontmatter (crafted multi-doc, billion-laughs YAML) | mitigate | `python-frontmatter` uses PyYAML's default safe loader (`yaml.SafeLoader` — no object instantiation, no code execution). Schema validation in `load_vault` requires id/type/title as `str` and `enabled` as Python `bool`; any other type causes the file to be skipped with a warning. Load loop catches `OSError` and `UnicodeDecodeError` per RESEARCH Pitfall 5; a YAML parse error from PyYAML raises `yaml.YAMLError` which is NOT currently caught — add it to the except tuple so one bad file does not crash the load loop. (Executor: include `import yaml` and `except (OSError, UnicodeDecodeError, yaml.YAMLError)` in Task 1.) |
| T-2-03 | Information Disclosure | `/health` returns `content_count` | accept | Reveals vault size only — no content, no IDs, no titles. The vault is non-sensitive customer-support Q&A content (per PROJECT.md scope). Operational value (knowing whether content is loaded) outweighs the minor information leak. |
| T-2-04 | Denial of Service | Unauthenticated `POST /content/reload` re-reads filesystem on every call | accept | v1 scope — no authentication layer exists across the API yet. Reload cost is bounded by vault size (operator-controlled, small Obsidian folder). Worst case: an attacker keeps the disk warm. Acceptable for single-tenant deployment.
